## 實際驗證

自動測試執行方式：`npm test`。語法檢查：`npm run check`。

本機資料復原修正後共 44 項測試通過。新增 13 項涵蓋逐項容錯、未知欄位、壞 JSON、重新載入後持續保護、離線及雲端載入期間新增打卡、分區讀取失敗、安全副本寫入失敗、帳戶切換與正常時間戳合併。整合測試執行應用程式實際的本機讀取及雲端合併函式，以假的 DOM、儲存與 Firestore 介面隔離正式資料。

本機啟動不再以嚴格備份檢查決定整份資料是否可讀。需要修復時，`_localRecovery` 隨本機存檔保留，但不寫入雲端 core；這時較新的本機時間不能觸發整份 core 覆蓋。必須成功從伺服器讀取 core 與其所有分區才解除保護。新打卡／抽卡按原有逐記錄規則合併，其餘離線修改先保留可下載副本，再採用雲端 core；頁面持續提示復原狀態及副本入口。未連線、分區缺失或無法保存副本時，保留本機修改並停止上傳。

- 四關由廣度搜尋逐關求解，必須收齊星光到出口；鎖匙、推箱和壓機關的教學關不能略過對應條件。
- 存檔資料驗證、碰撞不可移動、撤銷快照不被改寫、重複完成不可再領首次獎勵。
- 六對配對、翻錯時禁止再翻、重複按同一卡、完成後禁止再結算、每日兩局獎勵上限。
- 備份日期、分數、資料形狀與識別碼；舊資料遷移；恢復時包含已清空的舊分區。
- 雲端佇列模擬：空分區寫入、失敗重試、等待期間新增修改、換帳戶停止舊 session、舊失敗不污染新帳戶。

## 驗證界線與後續

- Google 真實登入、正式 Firestore 規則、兩部裝置同時寫入未在此工作環境實測；本次沒有操作正式帳戶的手帳資料。合併前建議在允許的測試網域與測試帳戶驗證登入、還原及跨裝置讀取。
