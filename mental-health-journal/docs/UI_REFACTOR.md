# 畫面模組重構

日期：2026-10-25。屬於草稿 PR #24；未合併、未切換正式網頁。

原本 `app.js` 有 11,826 行，混合插畫、頁面、事件、寵物與遊戲狀態。現在入口為 172 行，負責依序啟動各功能、登記頁面和統一重繪。畫面與玩法保留，執行時仍是靜態 HTML／CSS／JavaScript，毋須打包或編譯。部署須一併保留完整 `js/` 目錄及 `.mjs` 檔案。

## 模組邊界

- `art/` 純粹產生 SVG，`data/` 存牌卡、寵物和文字資料；可在 Node 直接測試。
- `cards/`、`pet/`、`games/` 及各手帳頁面各自管理畫面和事件。每個功能提供具名的初始化函式，由 `app.js` 只呼叫一次。
- `state.mjs` 對外提供 ES module 的 live binding。雲端載入或還原備份替換整份狀態後，各模組會讀到同一份新資料。
- 導航只呼叫啟動入口登記的 render／離場函式；寵物分頁和抽卡分頁也採用同樣做法。功能模組不反向匯入 `app.js`，模組圖沒有循環依賴。
- `storage.js`、`sync.js`、`core.js`、`adventure.js`、`auth.js` 保留原有可獨立測試的邊界。`shared/` 集中 DOM、日期、草稿與下載等共用工具。

`npm run check` 會遞迴檢查 JavaScript 語法、靜態 import／re-export 的目標與具名匯出，以及循環依賴；格式檢查亦涵蓋新目錄。大型 SVG 模組主要是繪圖字串，不再與頁面操作混在一起。

## 操作測試發現並獨立修正的問題

1. 抽卡等待回應時換帳戶，舊結果原本會被丟棄，但 `ritual` 狀態未清除，輸入框會一直停用。現在換帳戶或替換資料會清理該次抽卡；舊回應亦不能解除新抽卡的忙碌狀態。
2. 已排程的揭牌動畫可能在換帳戶後顯示舊解讀。延遲動作現在綁定原狀態、帳戶 session 與抽卡代次，離開該 session 就取消。
3. 換帳戶時，畫面曾在草稿 owner 更新前重繪。如果隨後讀取雲端失敗，就會留下上一個帳戶的草稿。現在先記錄新 owner 再通知畫面；舊草稿仍以原 owner 保留。
4. 外出、拋球、湖畔倒數、配對暫存、相片編輯與卡牌放大視窗在帳戶／資料切換時統一清理。拋球再玩按鈕改用 `data-start-ball`，避免與原入口重複使用同一個 HTML id。

- 五球完成、動畫中離場；湖畔倒數離場取消。
- JSON 下載／匯入、舊資料副本、跨頁顯示、清除；損壞資料的復原提示下載及收起。

- 切換後雲端失敗時不帶出舊草稿，舊草稿仍保留；習慣、證據、階梯及應急卡編輯。

測試命令見 [README](../README.md)。瀏覽器測試使用隔離的 localStorage 和合成資料，封鎖外部請求；帳戶測試只替換 Firebase SDK 邊界，仍執行實際 `auth.js`、`storage.js` 與畫面模組。

## 提交與合併界線

插畫抽離、畫面拆分、操作修正、瀏覽器／CI 測試和說明分開提交，便於按變更種類審閱。未改寫先前已公開的 commit，也沒有把含邏輯變更的 commit 加到 blame 忽略名單。

這些瀏覽器測試不涵蓋真實 Google OAuth 回程、Safari／Firefox 或兩部真實裝置同時寫入。既有同步仍使用 core 整份文件的時間戳策略；這輪沒有重寫並行衝突處理。合併前仍須按 [Firebase 切換說明](FIREBASE.md) 補搬舊專案新增記錄，再切換正式網頁。
