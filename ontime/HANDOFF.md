## 2. 用戶的硬性要求（不要違反）

1. **不可以改計算規則**：工作日歸屬（36 小時規則、起床做分界）、收入、工時。只改「怎樣記」和「怎樣看」。
2. **跨夜一定要對**：任何涉及時間的改動，都要加跨午夜、連續兩晚夜班、夏令時間的測試。
3. **不要閃爍、閃光、跳動的動畫**（用戶說傷眼）。
4. **不要賽博朋克或深色霓虹風格**。
5. 用戶想要 **現代、專業、有「進階工具」感，不要像玩具**；桌面版要有真正桌面網站的感覺。
6. **流程**：開分支 → PR → 用戶自己合併。不要直接 push 到 `main`。
7. **每次發版**：`sw.js` 的 `VERSION` 加一，同時更新 `tests/r9-sw-cache-cleanup.test.mjs` 裡的版本號和舊快取清單。

## 3. 怎樣跑

```bash
cd ontime
npm test                      # 已設定 TZ=America/Toronto；目前 250 個全過
python3 -m http.server 8000   # 打開 http://localhost:8000/index.html?nosw&now=2026-11-13T22:30
```

- `?now=...` 固定「現在」時間；`?nosw` 不載入 service worker（避免快取舊檔）。
- 示範資料：「我的／設定」頁 → 載入示範資料（按鈕 `data-action="demo"`，會再問一次確認）。
- 主要檔案：
  - `js/logic.js`：所有計算（純函式，最好測）
  - `js/actions.js`：寫入資料
  - `js/app.js`：事件處理、渲染迴圈
  - `js/views/*.js`：每一頁的 HTML
  - `css/app.css`：全部樣式
  - `DESIGN.md`：設計手冊，每版都要更新

### 5a. Bug 修正（已完成，已測試）

用戶截圖的問題：某一趟的「上班」被記成週日 01:14，但「出門」和「下班」都是週一。整趟面板因此一直報「次序不對」，而且改不到。

- `resolveTripDetail`（`logic.js`）：如果是**原有紀錄之間**次序不對（早過上一格，或者遲了一整天以上），就按次序重新排，並把重排的格放進 `repaired` 列出來。
  - 面板頂會顯示「『上班』記成 週日 11/15，已按次序改成 週一 11/16」，按「儲存整趟」就修正。
  - 如果次序不對是**用戶剛剛改的格**造成的，仍然照舊報錯，不會自動改。
- **新的一趟**：未手動揀過實際日期、而第一格是凌晨 4 點前，實際日期自動設為工作日的**隔天**。
  - 原因：工作日由起床開始，凌晨 4 點前仍算前一個工作日。
  - 用戶自己揀了日期就照用戶的。
- 加了 3 個測試（在 `tests/trip.test.mjs` 最底），250 個全過。
