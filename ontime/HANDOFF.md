## 1. 這是什麼

- **App**：OnTime，Dicky 自用的上班／通勤／睡眠／用餐紀錄 PWA（純 HTML + JS 模組 + CSS，沒有 build 步驟；可選 Firebase 同步）。
- **倉庫**：`hasonk200/claude-mini-store`，資料夾 `ontime/`。主分支 `main`。
- **用戶情況**：做夜班外送／倉庫，經常跨午夜，大約早上 6–7 點到家，星期日放假。最怕「日期撈亂」。
- **語言**：介面用繁體中文；跟用戶對話用廣東話或繁體中文都可以。

## 2. 背景：為什麼要改

用戶已經改了很多版（main 上由 2.0 到 2.30），仍然覺得這個 app「好難用」，要求「全面檢查，並用設計去改善」。以下是逐項找到的原因，也是 2.31 之後每一個改動的來由。

### 問題一：資料常常錯，尤其是日期
- 用戶做夜班，一班會跨過午夜。
- 每一筆紀錄都要分清兩個日期：
  - **工作日**：這班算哪一天。
  - **實際日期**：時鐘上真正是哪一天。
- 舊版 bug 多、日期經常錯。用戶要逐筆對照自己的追蹤 App 數字（所以有「已驗證」勾選）。
- 錯得太多，用戶另外做了一個**臨時應急版** `commute-log-temp`（同一個倉庫，有自己的 Firebase 同步）。打算之後把紀錄搬回 OnTime。
- 更早有一個 ChatGPT 做的版本，會自動把紀錄綁定到當天的班次。用戶喜歡這一點，但不想太死板，要可以揀返另一班或另一個工作日。

### 問題二：記一筆太麻煩，結果唔想記
- **記瞓醒**：要填四格（入睡日期、入睡時間、起床日期、起床時間）。預設是 23:00 → 07:00，但用戶通常朝早先瞓，所以次次都要改。
- **記食飯**：要入一張八欄的表格。首頁的入口在最底，要捲兩版多才見到。
- 結果：用戶瞓醒、食完之後都**唔想補記**。
- 惡性循環：漏記睡眠 → app 找不到工作日的分界（工作日由起床開始）→ 要用後備規則去估 → **日期更亂**。

### 問題三：補返工和通勤要行好多步
- 舊的補登流程是「工作日 → 類別 → 班次 → 哪一步 → 時間」，一班有七個時間就要行七次。
- 反而臨時版好用，因為它是「一個日期、七格時間、一次存」。
- 所以 2.32 把同一個做法搬回 OnTime（整趟面板）。

### 問題四：舊紀錄日期錯了，改不到
- 用戶截圖：某一趟的「上班」被記成週日 01:14，但「出門」和「下班」都是週一。
- 整趟面板一直報「次序不對」，用戶自己改不了。
- 修正見 6a。

### 問題五：外觀似玩具
- 舊外觀：圓泡泡圖示、很粗的字、萊姆綠、卡通街景插畫。
- 用戶覺得似玩具，要求**整個 app** 換成現代、進階、專業的感覺。
- 用戶之前揀過日系簡約（無印風），**不要**賽博朋克或深色霓虹。
- 新外觀見 6b。

### 由此得出的原則（之後的改動都照這些做）
1. **只改「怎樣記」和「怎樣看」，不改計算規則**。工作日歸屬、收入、工時的規則已經有大量測試，而且用戶對過數。
2. **用戶只答「幾點」或者「幾耐之前」，日期由 app 推算**。
   - 一覺不會超過 24 小時，所以入睡日期只有一個可能。
   - 七格時間由上而下排，鐘數細過上一格就是隔天。
3. **存之前一定顯示確認**：真實日期、時長、計入哪個工作日都寫出來。不合理的時間（重疊、次序倒轉、未到的時間、相隔太耐）直接擋住。
4. **常用的事一撳就完成，少用的收起來**。完整表格保留，用來補舊日子。

## 4. 怎樣跑

```bash
cd ontime
npm test                      # 已設定 TZ=America/Toronto；目前 250 個全過
```

  - 檢查「載入示範資料」「清除全部」會不會覆蓋或者刪除真實資料。
  - 如果會：要有清楚警告，並且先自動備份一份。或者把示範資料移到不易誤撳的位置。
  - **這是重點**：用戶的真實資料不可以有任何意外。
- 匯出、匯入（JSON、CSV）要在真實資料上試過可以來回還原。

### 8.9 臨時版紀錄匯入 OnTime

- **來源**：臨時版 `commute-log-temp/`（同一個倉庫）。它用自己的 Firebase（collection `apps`、`users`），也可能有本機 localStorage。
- **步驟：**
  1. 先讀懂臨時版的資料格式（七個時間和日期怎樣存）。
  2. 在 OnTime 設定頁加「從臨時版匯入」：可以貼上臨時版的匯出 JSON，或者用同一個 Google 帳戶直接讀取。
  3. **匯入前顯示預覽**：幾多趟、每趟的工作日和七個時間、哪些和現有紀錄重複。用戶確認後才寫入。
  4. 重複的紀錄不可以寫兩次；要可以復原。
- **測試**：跨夜的趟次匯入之後，工作日和實際日期都要正確。
