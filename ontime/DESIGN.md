# ONTIME 設計手冊

更新：2026-10-14（America/Toronto）。這份手冊說明新版 ONTIME（Daybreak 設計）為什麼這樣做、需求從哪裡來、每一頁負責什麼，以及畫面和程式的規則。之後改動需求、時間規則或畫面時，請一起更新這份文件，寫清楚「需求是什麼、為什麼這樣做、目前做到了哪裡」。

---

## 1. 這個 App 要幫我做什麼？

我想知道自己每一個工作日發生了什麼：幾點出門、搭車、上班、下班、回家、吃飯和睡覺。記錄要像日常習慣一樣輕鬆，按一下或補一個時間就可以，之後由 App 把事情接起來。

我的作息常常是夜班：週一晚上上班，週二早上下班，週二白天才睡覺。App 要讓我同時看懂兩件事：

- 這是我的**週一工作日**（以上班日期命名）；
- 這件事**實際發生在週二**（真實日期、星期和時間）。

這是整個設計的核心。其他功能都要配合真實作息，減少重複輸入，並讓「已知、預計、未知」容易分辨。

## 2. 我的需求，以及設計怎樣回應

| 我的需求 | 新版的設計 | 原因 |
| --- | --- | --- |
| 夜班過了午夜，仍然知道自己在哪個工作日 | 工作日以上班日期命名；每個事件另外顯示實際日期與星期；跨過午夜加上「隔日 +1」標籤，時間線出現「午夜 · 進入週二，仍屬週一工作日」分隔 | 生活的接續和日曆日期兩樣都要看得懂 |
| 不想自己整理跨日紀錄 | 首頁、時間線、睡眠、用餐依班次自動接續；睡眠可以手動改所屬工作日 | 自動配對處理大部分情況，也留更正入口 |
| 想知道睡前還有多少時間 | 「睡前未安排時間」與「距離預計入睡」分開顯示 | 倒數包含工作，未安排時間才是真正的空檔 |
| 自己記下的時間最重要 | 實際紀錄用實心，計畫用虛線，未知用斜紋或「—」 | 計畫不代表已經發生，三者永遠不混在一起 |
| 補登一個時間，不想面對大表格 | 先選環節，再填日期和時間；其他選項收起來 | 一次完成一件事，避免改錯別的時間 |
| 出門後有搭車，回家前也有搭車 | 去程、回程搭車分開記錄；可以「步行直接抵達」「直接到家」 | 通勤不一定每次都有搭車 |
| 上班時也可以吃飯 | 用餐可以和工作重疊，不扣休息、不影響薪資，合計時只算一次 | 吃飯和出勤是不同的紀錄 |
| 用餐想加相片 | 每餐一張相片，裝置上縮小到最長邊 1280px、256 KiB 以內 | 相片跟同一餐保存和同步 |
| 外送按單收入，不能只用時薪算 | 每份工作可選時薪、按單（整次實收＋訂單數）或不計薪；「未填」和「0」分開 | 工時不等於按單收入 |
| 沒有網絡也要記錄 | 先寫入本機 IndexedDB；Service Worker 快取 App 外殼 | 按儲存時不應等網絡 |
| 換裝置也看得到 | 用 Google 登入，同步到 Firestore | 和舊版一樣的使用方式 |
| 手機上要像 App | 可安裝的 PWA、底部浮動導覽、固定在底部的主按鈕 | 打卡要容易按、容易重開 |
| 也要在電腦上用，而且不是把手機版放大 | 桌面版有側邊欄、四行時間軸、紀錄表與檢視面板、大月曆 | 大螢幕適合一次看全貌和用滑鼠修改 |
| 畫面要清新、高級 | Daybreak 設計語言：紙白底、墨黑主角、萊姆綠標示「現在」 | 第一眼就知道現在要做什麼 |
| 頂部想要有動畫 | 會跟著時間和狀態變化的街景 | 讓每天打開 App 有一點樂趣 |
| 晚上用不刺眼 | 深色模式：跟隨系統，或在「我的」手動選擇 | 夜班和睡前常在暗處使用 |
| 舊版資料要能搬過來 | 匯入時自動辨認舊版備份格式並轉換 | 不用重新輸入以前的紀錄 |

## 3. 「我的一天」怎樣計算？

### 3.1 工作日：由起床到下一次起床

一個工作日由一次**主睡眠起床**開始，到下一次主睡眠起床為止。下班後的用餐和睡眠，都屬於前一個工作日；睡醒之後，才是新的工作日。

| 實際時間 | 事件 | 歸在哪個工作日 |
| --- | --- | --- |
| 週三 14:10 | 起床 | 週三（新的一天開始） |
| 週三 23:20 | 上班 | 週三 |
| 週四 07:40 | 下班 | 週三 |
| 週四 08:32 | 早餐 | 週三 |
| 週四 12:59–21:22 | 睡眠 | 週三 |
| 週四 21:22 | 起床 | 週四（新的一天開始） |
| 週四 21:40 | 用餐 | 週四 |

- **主睡眠**：實際睡了 4 小時或以上（間隔少於 30 分鐘的兩段先合併計算）。較短的小睡不會切開一天。
- **手動分界**：在睡眠的修改面板勾「當作工作日分界」，即使不到 4 小時也算主睡眠。勾了之後，這段睡眠之後的所有紀錄都會歸到下一個工作日，所以只該用在真的換日的那次起床，不要拿白天的小睡來勾。
- **命名**：用起床的日期；凌晨 4 點前起床，仍用前一天的日期。
- **歸屬**：出勤按上班時間、通勤按出門時間、用餐按開始時間、睡眠按入睡時間，看它在哪一次起床之後。
- **後備規則**：之前 36 小時內沒有主睡眠起床紀錄（例如漏記了睡眠）時，出勤按上班日期，睡眠接回入睡前 24 小時內結束的出勤，其他按日曆日期。
- **手動指定**：睡眠的「所屬工作日」可以手動改，手動指定永遠優先。
- **補登跟著你揀的工作日**：在補登面板補「上班」或行程時，這一班和行程就固定屬於面板上揀的工作日，不會因為起床邊界被算到別天；只有首頁即時按掣的紀錄才用自動規則。還沒有上班紀錄的行程（例如只補了「到家」）也會顯示。
- **已驗證**：每個時間點都可以手動打勾「已驗證」，表示你確認這個時間是對的。打勾的地方：補登面板、時間線修改面板、用餐表單，以及時間線上每個時間旁的小圓圈（點一下直接打勾／取消，不用開面板）。已驗證的時間在時間線會顯示綠色勾勾和「已驗證」標籤，工作日卡片標題旁顯示「已驗證 N／M」。沒打勾 = 還沒驗證，不代表不準。計畫不能打勾。打勾只是標記，不影響任何計算；改時間時勾勾不會自動取消。（先前的「準確／大約」和「待確認」已拿掉；舊資料裡殘留的 approx 欄位不使用。）
- **輸入時間**：點時間的數字直接用鍵盤打（1830、930、18 都可以，離開時整理成 18:30）；點旁邊的時鐘才打開手機的時間選擇器（iOS 滾輪、Android 時鐘）。打錯的時間會提示，不會送出。
- **存了就看得到**：補登做不到時（例如沒有上班紀錄就補「下班」）一定顯示原因，不會出現「已儲存」卻看不到。
- **日曆日**：當地 00:00 到下一個 00:00。跨日工時按實際日期拆開；收入按出勤開始的日期計算，不會算兩次。

### 3.2 打開 App 時先看哪一天？（`currentWorkday`）

有主睡眠紀錄時，就是「現在」所屬的工作日（最近一次主睡眠起床之後）。沒有的話，按以下順序：進行中的出勤 → 進行中的睡眠 → 還沒到家的通勤 → 36 小時內完成的出勤（下一個排班已開始則切換）→ 24 小時內的下一個排班 → 今天的日曆日期。

### 3.3 睡眠歸屬（`sleepWorkday`）

- 睡眠屬於入睡前最近一次主睡眠起床的那一天；修改歸屬不會改入睡或起床時間。
- 時間線在主睡眠結束處標示「起床 · 週X工作日開始」。

### 3.4 實際、預計、未知

- 睡眠一旦開始記錄，就用實際區間；還沒起床時只計到現在，預計起床時間不當作已經睡過。
- 新的睡眠計畫不預填時間；可以「沿用最近一次時段」，但只建立計畫，不會產生實際紀錄。
- 近七天平均只計有完整實際紀錄的工作日，重疊的睡眠只算一次，沒有紀錄的日子顯示「—」。
- 沒有抵達、離開或睡眠時間，就保留未知，不借用別班的紀錄來填滿畫面。

### 3.5 睡前時間預算（`beforeBedBudget`）

- **距離預計入睡**：現在到下一個睡眠計畫的單純倒數，仍包含工作和通勤。
- **睡前未安排時間**：同一段時間，扣除剩餘工作、預估通勤（設定裡的去程／回程分鐘）、已確認的用餐和其他睡眠計畫；重疊的時間合併後只扣一次。
- 沒有睡眠計畫時，首頁改為顯示「已清醒」（由最後一次起床到現在）和「過去 24 小時睡了」（把分段睡眠加起來，並畫出每一段）；不會用午夜代替計畫。最多看未來 8 天內的計畫。

## 4. 頁面與功能

導覽：手機用底部浮動列（今天、時間線、＋新增、睡眠、統計）；桌面用左側欄（今天、時間線、一週與班表、睡眠、用餐、統計與收入、我的）。

| 頁面 | 手機 | 桌面 |
| --- | --- | --- |
| **今天** | 頂部動畫場景；現在狀態卡與主按鈕（記錄下一個環節）；睡前時間兩格；工作日色條；這趟通勤與出勤 7 步進度；快捷（用餐、補登、休息、收入）；下一餐 | 另加四行時間軸（工作、通勤、用餐、睡眠）、這個工作日的紀錄表，點一行在右邊檢視面板直接改時間 |
| **時間線** | 工作日／日曆日切換；本週日期列；事件列表（點一項可改時間）；工時、通勤、睡眠小結 | 全寬四行時間軸在上，列表與小結在下 |
| **一週與班表** | 由時間線右上角「班表與月曆」進入 | 一週時間軸（按工作日由 18:00 起排，或按日曆日 00:00 起排，夜班會標「接續」）；本週合計；範本；最下面的大月曆：點一天看／加／刪班次和標記休假，「多選日期」可以批次套用範本 |
| **睡眠** | 計時圓環（實心＝已睡，虛線＝計畫）；現在入睡／起床；所屬工作日；近七個工作日；睡眠計畫 | 兩欄排版，下面加最近睡眠表 |
| **用餐** | 待確認的安排；記一餐（日期、開始、結束、已吃／只是安排；選填餐點、地點、備註、相片）；這個工作日的用餐 | 左邊清單、右邊表單 |
| **統計與收入** | 週／月切換；工時、時薪計薪、按單實收、通勤、平均睡眠；每個日曆日的工時（分開「前一工作日帶過來」和「當天開始」）；出勤明細；按單收入可直接填寫 | 五個重點數字一排；可按工作篩選；匯出 CSV |
| **我的** | 個人設定（稱呼、預估通勤時間）；外觀（跟隨系統、淺色、深色）；工作設定；雲端同步；資料與備份；安裝與示範 | 兩欄排版 |
| **補登面板** | 由下往上的面板：選所屬工作日 → 選環節（去程、出勤、回程、生活）→ 填實際日期和時間；快捷「現在」「−15 分」「用預計」 | 置中的對話框；按 `N` 開啟，`Esc` 關閉 |

### 每天用的小幫手

- **復原**：打卡、休息、入睡、起床、確認或刪除用餐後，提示裡有「復原」按鈕（約 6 秒），可以取消上一步。
- **主畫面捷徑**：把 App 加到主畫面後，長按圖示可以直接記「出門、上班、入睡、記一餐」（視乎手機系統是否支援）。
- **按需要收起**：沒有範本和排班時，範本卡縮成一行；這段期間沒有時薪班次時，統計頁改顯示「平均每班工時」。
- **顏色說明**：時間軸下的說明直接寫工作名稱和它的顏色。
- **距離上一餐**：今天頁和用餐頁顯示「距離上一餐已過 X 小時 Y 分」，超過 6 小時用用餐色提醒。
- **最近常吃**：記一餐時，餐點和地點下面有最近 30 餐裡最常出現的前 5 個標籤，點一下就填入。
- **鍵盤（桌面）**：`N` 補登、`Space` 主按鈕（可復原）、`[` `]` 或 `←` `→` 切換工作日、`Esc` 關閉面板。
- **手機場景**：手機版場景比較矮，打開 App 就看得到主按鈕。

### 主按鈕怎樣決定下一步？

環節順序：出門 → 上車 → 抵達 → 上班 → 下班 → 上車 → 到家。主按鈕記錄「最後一個已記錄環節之後的第一個空格」，並按情況提供捷徑：還沒出門時可以「直接上班」，等車時可以「步行直接抵達」，下班後可以「直接到家」；工作中可以開始／結束休息；空閒時可以「現在入睡」。

## 5. 設計語言 Daybreak

### 5.1 原則

1. **工作日優先**：以上班日期命名一天，真實日期永遠一起顯示。
2. **實際 › 預計 › 未知**：實心＝已發生，虛線＝計畫，斜紋或「—」＝不知道。
3. **一次一件事**：每個畫面只有一個主要按鈕；選填內容收起來。

### 5.2 顏色

| 用途 | 淺色 | 深色 |
| --- | --- | --- |
| 底色 | `#F4F5F1` 紙白 | `#0E1116` |
| 卡片 | `#FFFFFF` | `#171B22` |
| 文字 | `#111418` 墨黑 | `#ECEFF3` |
| 次要文字 | `#5B636E` | `#A3ABB7` |
| 主要按鈕 | 墨黑底、白字 | 淺灰底、墨黑字 |
| 狀態卡 | 墨黑 | `#1F2530` 加細邊 |
| 「現在」 | 萊姆 `#CFF56A`（上面的字一律墨黑） | 同左 |

類別色只用在色塊、圓點和圖示，文字用同色系的深色版本（深色模式改用淺色版本），對比至少 4.5:1：

| 類別 | 色塊 | 淺色底色／文字 |
| --- | --- | --- |
| 工作 | `#FF8A3D` | `#FFE9DA` / `#8A3D0A` |
| 外送／第二份工作 | `#18A55C` | `#DDF5E7` / `#0F5F35` |
| 通勤 | `#1FB8A8` | `#D9F4F0` / `#0E7C71` |
| 睡眠 | `#6B5CFF` | `#EFEDFF` / `#4B3FD9` |
| 用餐 | `#FF5E7E` | `#FFE1E7` / `#C9284C` |
| 到家 | `#7DB52B` | `#E9F7D0` / `#3E5A0A` |

所有顏色都定義為 CSS 變數（`css/app.css` 開頭）。深色模式只重新定義變數，元件本身不寫死顏色。

### 5.3 字體

- 數字和英文：Manrope（800 字重做大數字，等寬數字）。
- 中文：Noto Sans TC。
- 層次：頁面標題 32–38 / 800；卡片標題 16 / 800；內文 15 / 400–600；說明 12 / 500。

### 5.4 元件

- **按鈕**：全圓角；主要（墨黑）、萊姆（深色卡片上的主要動作）、線框、柔和、危險。觸控目標至少 44px。
- **卡片**：圓角 24（桌面 28）；淺陰影，不用邊框。
- **圖示泡泡**：類別底色＋深色圖示；已完成右下角有勾；目前一步是萊姆底加墨黑框；未來是虛線白底。
- **圖示**：自己繪製的線條圖示（門、巴士、定位、公事包、旗、屋、餐具、杯、月亮、太陽等），不用 emoji。
- **分段切換**：灰底膠囊，選中項目白底。
- **時間軸**：手機一條色條，桌面四行；刻度按實際寬度自動隱藏重疊的標籤，午夜刻度優先保留。

### 5.5 頂部動畫場景

- **天色**：清晨（5–7 點）、白天（7–17 點）、黃昏（17–19:30）、夜晚，按當地時間；太陽 6–18 點、月亮 18–6 點沿弧線移動。
- **小人跟著狀態**：在家（白天會揮手，晚上窗口有人影）、出門走向巴士站、搭車（城市和路燈往後移，排氣冒煙）、走向公司、上班（輸送帶送出箱子）、休息喝咖啡、下班走回巴士站、睡覺（窗戶變暗、冒 Zz）。
- **環境**：車流、路燈（晚上亮）、樹會擺動、白天有飛鳥、晚上有星星、流星和屋頂上的貓。
- **互動**：點一下場景，小人會跳一下。
- 手機用較窄較高的構圖（640×400），桌面用寬構圖（1200×300），標題不會壓到房子。
- 系統設定「減少動態效果」時，動畫會停止。
- 預覽所有狀態：`tests/hero-gallery.html`（加 `?compact` 看手機版）。

## 6. 程式怎樣建成？

### 6.1 技術選擇

- 不需要建置的靜態網頁 App：HTML、CSS 和原生 JavaScript 模組，放到 GitHub Pages 即可。
- 畫面由各頁的函式產生 HTML 字串；按鈕用 `data-action`、表單用 `data-form`，由 `app.js` 統一處理。
- 時間用 `Date` 和當地時區；所有時間戳記是毫秒數字，日期鍵是 `YYYY-MM-DD`。夏令時間由 `Date` 處理，工時用時間戳記相減，不假設一天一定是 24 小時。

### 6.3 資料

| 資料 | 內容 |
| --- | --- |
| `jobs` | 工作名稱、顏色（主要／外送）、計薪方式、時薪 |
| `shifts` | 預定班次（開始、結束、工作） |
| `templates` | 班次範本（名稱、工作、開始、結束；結束早於開始代表隔日） |
| `sessions` | 實際出勤：上下班、休息、計薪快照（方式和時薪）、按單實收、訂單數、備註 |
| `journeys` | 出門、去程上車、抵達、離開、回程上車、到家，以及對應的出勤 |

每種紀錄只改自己負責的資料：記錄用餐不會改出勤；改工作的時薪只影響之後的出勤，舊出勤保留當時的計薪快照。

### 6.4 離線、同步與備份

- **本機**：所有修改先寫入 IndexedDB，沒有網絡照樣可以用。
- **雲端**：用 Google 登入後，資料存到 Firebase 專案 `dicky-quota-tracker-2026` 的 `users/{uid}/apps/ontime`；相片另存為 `users/{uid}/apps/ontime-photo-{餐次 id}`，避免超過單份文件 1 MB 的上限。
  - 第一次在一部裝置登入：以雲端為準，再加入只存在這部裝置的紀錄。
  - 之後每次修改自動上傳，其他裝置即時更新。
  - 每筆紀錄有 `updatedAt`；刪除改為加上 `deletedAt` 的刪除標記（30 天後清除）。同步時逐筆比較，較新的版本勝出，所以兩部裝置改不同紀錄不會互相覆蓋。上傳時用 Firestore 交易，先讀雲端最新版本、合併後才寫回。
  - 兩部裝置同時改**同一筆**紀錄時，以較晚修改的為準。
- **持久化儲存**：開啟時向瀏覽器申請持久化儲存，設定頁會顯示是否已受保護。
  - 部署的網址要在 Firebase Authentication 的授權網域內；Firestore 規則要允許登入者讀寫自己 `users/{uid}` 底下的文件。
- **JSON 備份**：包含所有紀錄和相片；匯入可以選「合併」或「取代」。
- **CSV**：每次出勤一行，包含各日曆日工時、休息、通勤、計薪、實收和訂單數。
- **舊版備份**：自動辨認 `dicky-ontime-backup` 格式，取每筆資料的最新版本，略過已刪除的紀錄，並用時間把通勤配對回對應的出勤。舊版的用餐偏好時段、每週工時目標、強調色目前沒有對應功能，會略過。

### 6.5 測試與發佈

- `cd ontime && npm test`：使用 `America/Toronto` 時區，涵蓋夜班跨午夜、下班後睡眠歸屬、切換到新工作日、睡前未安排時間、休息扣除、日曆日分配、按單收入、夏令時間結束當天、同步合併、舊版匯入。
- 發佈新版本時，把 `sw.js` 的 `VERSION` 加一，使用者會看到「有新版本」提示。
- 開發時可以在網址加 `?now=2026-10-13T03:18` 固定時間、`?nosw` 停用快取。

## 7. 已知限制與之後可以做的事

### 現在需要知道的限制

- 自動配對靠時間範圍判斷，不能確定每段睡眠是主睡眠還是小睡；多份工作、漏打卡或很長的空檔可能需要手動改所屬工作日。
- 沒有睡眠計畫就不計算睡前未安排時間。
- 兩部裝置同時改同一筆紀錄時，較早的修改會被較晚的取代（不同紀錄不受影響）。
- 按單收入需要自己填寫，沒有連接外送平台。
- 「自動」只是時間規則和配對，沒有 AI 在背景讀取私人紀錄或自動寫入實際時間。

### 可以再討論，尚未實作

- 逐筆的版本紀錄與衝突處理（像舊版的 revision 設計）。
- 用餐提醒與按偏好時段的建議。
- 更清楚地區分恢復睡眠、小睡和多班次。
- 根據多次實際紀錄提供作息建議，顯示依據並由我確認。

## 8. 改動後怎樣檢查有沒有改壞？

最重要的情境：週一夜班、週二下班、回家、白天睡眠，仍然在同一個工作日看到；每個事件的真實日期、星期和時數都正確。朝九晚五也用同一套規則。

此外要檢查：

- 實際睡眠優先於計畫；計時未結束、跨午夜、夏令時間和重疊紀錄都算對。
- 補登一個環節只改那一個時間，其他打卡、收入、休息、備註保持不變。
- 工作中吃飯可以儲存，時間不重複扣除，出勤和薪資不因用餐改變。
- 按單收入的「未填」、0 和已填金額分開顯示；跨日收入只算一次。
- 相片、睡眠歸屬和其他紀錄在離線、重開、同步和 JSON 備份後仍然保留。
- 手機（390px）、桌面（1280px、1920px）、淺色和深色、沒有資料和有資料時，每一頁都可以用，刻度和文字不重疊。

## 搭車資訊
去程／回程搭車可以另外記錄交通工具與上車地點（journey 的 `rideMode`、`rideFrom`、`ride2Mode`、`ride2From`，全部選填）。補登「搭車」時會出現交通工具晶片和地點輸入，並列出最近用過的地點；時間線事件、CSV 匯出都會帶上。這些只是附註，不影響工作日或通勤時數。
